# マウス全身 microCT（造影・腫瘍）データセット（Virtual Rodent Lab 体験版用）

Virtual Rodent Lab — 体験版（`naomitsu-ozawa/virtual-rodent-la-trial`、以下 VRL）で
そのまま読み込める形に変換した、造影剤ありマウス全身 microCT の DICOM 一式とプロジェクトファイルです。
ネイティブ（非造影）版データセット（`wholebody_m01`）と同じ形式・同じ手順で作成しました。
リポジトリ自体には一切手を入れていません（読み取りのみで仕様を確認し、成果物はこのフォルダに置いています）。

## 中身

| パス | 内容 |
|---|---|
| `dicom_ct/` | 全身 CT（造影）の DICOM シリーズ（242 ファイル、`ContrastCT_0001.dcm` 〜 `ContrastCT_0242.dcm`、約 5.1 MB） |
| `dicom_labels/` | 臓器＋腫瘍ラベルの DICOM シリーズ（242 ファイル、`ContrastLabels_0001.dcm` 〜、約 2.7 MB）。CT と同一グリッド |
| `wholebody_m01_contrast.vrlab` | VRL プロジェクトファイル（CT シリーズに紐付き、ラベル由来のセグメントマスク 3 件＋解析領域 11 件（名前・色・3D ラベル付き）入り） |
| `sample.json` | VRL 練習データ形式のメタ情報（出典・ライセンス・変更点）。アプリ自身の `parseSample` で検証済み（エラー 0） |

スクリーンショットは本一式には含まない（撮影は別途実施）。

## VRL での使い方

1. VRL で `dicom_ct` フォルダの DICOM を読み込む（CT シリーズが自動選択される）。
2. プロジェクトファイル `wholebody_m01_contrast.vrlab` を読み込むと、表示ウィンドウ（中心 100 / 幅 1200）と
   セグメント（骨・肺・造影領域）が適用される。セグメントの中身は元データの手動セグメンテーション
   そのもの（下記「プロジェクトファイルの中身」）で、閾値の近似ではない。
3. `dicom_labels` は別シリーズとして読み込める（値は元のクラス番号のまま 0〜13、対応表は下記）。
   CT と ImagePositionPatient グリッドが完全一致するので、外部ツールでもボクセル単位で対応づけられる。

## 選んだスキャンと根拠

zip 内には 85 スキャン分（個体 M01〜M07 系 × 時点 −1 h〜240 h、造影系列）のフォルダが入っている。
本変換では **M01 の 0.25 h**（個体 M01、系列の最初の個体・最も早い時点。−1 h 時点を持つのは M03 以降のみ）を選んだ。根拠:

- ネイティブ版で採用したのと同じ個体・同じ時点であり、非造影／造影の対で比較できる。
- この時点には独立した手動セグメンテーションが 2 件（Organ1_280 / Organ2_280）付いており、相互比較で品質を評価できる。
- **腫瘍ラベルが実在する**（次節）。M01 の腫瘍は時点とともに増大する実測が得られている
  （Organ2 系/Organ 系の実測で 0.25 h: 7,525 → 240 h: 46,694 ボクセル）。

各フォルダの中身は NIfTI ではなく **Analyze 7.5 形式**（`.hdr`/`.img` ペア）だった
（CT140 = 0.14 mm グリッド、CT280 = 0.28 mm グリッド、Organ*_280 / Organ_280 = 臓器セグメンテーション、
Bed = 寝台・全身等のセグメンテーション、各々に `.cls` のクラス定義ファイル付き）。

- 使用したのは **CT280**（154 列 × 121 行 × 242 スライス、0.28 mm 等方。ネイティブ版の 142×105×200 より
  撮像範囲が広い）。臓器セグメンテーションがこのグリッド上で作られているため、ラベルのリサンプリングが一切不要になる。
- セグメンテーションは **Organ2_280** を採用した（ネイティブ版の選択と揃えた）。
  骨マスクの高 HU 整合は Organ1_280 / Organ2_280 とも良好だった（HU ≥ 400 に対する precision: Organ1 0.98 / Organ2 0.97）。
  観察者間 Dice（実測）は 心臓 0.894、肝臓 0.893、膀胱 0.885、肺 0.876、腎臓 0.866、脾臓 0.854、
  骨 0.963、気管 0.879、胃 0.786、**腫瘍 0.718**、腸 0.565、筋肉 0.136 だった。

## 腫瘍について（実物確認の結果）

- **腫瘍クラスは実在した。** 採用した `Organ2_280.cls` では **クラス 10 = “Tumor”**、実測 **7,525 ボクセル
  （= 165.19 mm³、1 ボクセル 0.28³ = 0.021952 mm³）**。CT 上の腫瘍内 HU 中央値は 98、
  位置は元グリッド z 64〜98（骨盤〜腹部の範囲）。造影版の全 85 スキャン中、腫瘍ラベルの無いものは無かった
  （各フォルダの .cls と実測ボクセル数で確認）。
- 注意点として、**クラス番号はファイルごとに異なる**（Imalytics が作成順に番号を振るため。
  例: Organ1_280 では Tumor = 9、Organ_280 系では 10 など）。本変換の対応は全て採用ファイル自身の
  `Organ2_280.cls` の ClassNames に基づく。
- Organ2_280.cls にはクラス 2 = “tmp” という作業用とみられる名前もあるが、このスキャンでは
  **ボクセル数 0**（実測）であり、データには含まれていない。

## 元データの実測結果（変換前の検査）

- CT280 の格納値は int16 で **−1000〜3716**。論文は「全ボクセルの強度は Hounsfield unit で校正
  （空気 −1000、水 0）」と明記しており、実測最小値もちょうど −1000 だった。**したがって格納値は HU である**。
  造影の反映として、肝臓内 HU 中央値は 295（ネイティブ版 M01 の実測 147 より高い）、腫瘍 98、筋肉 134 だった（元データのまま、換算はしていない）。
- 寝台（Bed）のクラス 1 がマウス全身を指すことを確認した（Organ2_280 のラベル済みボクセル 269,318 のうち
  269,216 が内包される。残り 102 ボクセルはセグメンテーション側が全身クラスの外側にはみ出して描いた分）。
- 体部マスク内 CT のパーセンタイル: 中央値 46、99% 点 1400。

## 変換内容（何をどう変えたか）

1. **クロップ**（元ボクセル座標）: 全身マスク（Bed クラス 1 ∪ 臓器ラベル）の bbox
   x 21〜134 / y 24〜89 / z 0〜241 に 5 ボクセルの余白を追加し、
   x 16〜139、y 19〜94、z 0〜241（z はラベルが両端まで届くため全域）とした。
2. **ダウンサンプルなし（倍率 1）**: クロップ後は **124 列 × 76 行 × 242 スライス** で、
   全軸とも上限 512 ボクセルを大きく下回るため、等方ダウンサンプルは不要だった（間隔は元の 0.28 mm のまま）。
   展開サイズは 124×76×242×2 byte = **4,561,216 bytes（約 4.35 MiB）** で、
   VRL のメモリ内処理の上限 256 MiB を大きく下回る。実寸は 34.72 × 21.28 × 67.76 mm。
3. **タグの付け替え**（シリーズとして成立させるため。ネイティブ版と同一規約）:
   - 新 Study / Series Instance UID（2.25.* 形式で生成）。元データ（Analyze 形式）には DICOM UID も
     撮像日も無いため、日付タグは変換日になっている。この点は各ファイルの DerivationDescription にも明記した。
   - CT シリーズ: SOP Class は CT Image Storage、Modality `CT`、ImageType `DERIVED\SECONDARY\AXIAL`。
     BitsAllocated / BitsStored 16、**PixelRepresentation 1（符号付き）** で HU の負値をそのまま保持。
     Rescale Slope 1 / Intercept 0。Window Center 100 / Width 1200（ネイティブ版と同
...[truncated 7370 chars]じ値とした。一般表示用の初期値で、値そのものは変えていない）。
   - ラベルシリーズ: Secondary Capture / Modality `SC`、ConversionType `WSD`、8-bit。
     **画素値は元のクラス番号そのまま**（並べ替え・振り直しはしていない）。
   - InstanceNumber は 1 始まり。ImagePositionPatient は新グリッドで再計算（原点 = クロップ始点×0.28 mm）。
   - 各ファイルに DerivationDescription (0008,2111) として変換内容を英語で記録。
   - 転送構文は Explicit VR Little Endian・非圧縮、1 スライス 1 ファイル、Part 10 形式。

## プロジェクトファイルの中身（セグメントマスク方式）

- 形式: ZIP + `project.json`（`format: "virtual-rodent-lab-project"`, `version: 1`、拡張子 `.vrlab`）。
- `dataset` フィンガープリントは、変換後 DICOM をアプリ自身の `groupSeries` に通して得た値そのもの
  （seriesUid `2.25.22382180526858512272408742249315939501`、124×76×242、spacing [0.28, 0.28, 0.28]）。
- 最終ファイルは、起動中の VRL アプリの中でセグメント編集状態（keep マスク）を設定し、アプリ自身の
  保存機能で書き出したものである
  （savedAt `2026-11-10T10:55:39Z`）。外部スクリプトで JSON を直接組み立てたファイルではない。
- **セグメントは閾値ではなく、元データの手動セグメンテーションのボクセルマスク（keep）で定義した。**
  閾値範囲はデータ全域（−1000〜3716）に開け、最終的なセグメントのボクセル集合は
  `範囲 ∩ keep マスク` = ラベル集合そのものになる（検証の節で集合一致を確認）。
  これにより、閾値法では分離できない寝台（ベッド）や空気はセグメントに一切混入しない。
- **解析領域は 11 件**（心臓・膀胱・腎臓・胃・筋肉・脾臓・肝臓・腸・腫瘍・肺・気管）。名前・色・マスクは、以前の子セグメント（`treeSegments`）のものをそのまま使い、アプリ自身の処理で解析領域に作り直した。各領域には 3D 上の名前ラベルを付けた。ラベル自体は `dicom_labels` に全クラス残っている。

| セグメント | 元クラス（Organ2_280.cls の名称） | ボクセル数 | 体積 (mm³) | 色 |
|---|---|---:|---:|:--|
| bone（骨） | Bone | 38,445 | 843.94 | #f3f0e8 |
| lung（肺） | Lung + Trachea | 27,326 | 599.86 | #6fb8d6 |
| contrast（造影領域） | 脾臓・膀胱・腎臓・心臓・胃・**腫瘍**・筋肉・肝臓・腸（9 クラス合体） | 203,547 | 4,468.26 | #c026d3 |
| soft / fat | —（無効） | — | — | — |

- **子セグメント（`treeSegments`）**: 親の keep マスクを構成する各クラスは、
  親の下位の「子セグメント」として個別に登録した（名前・色・表示切替を個別に持つ本物のセグメント）。
  子のボクセルは親の表示から差し引かれるため、contrast と lung では親自身の表示は **0** になり、
  表示は全て子が担う（bone には子がなく、親がそのまま表示する）。子同士は互いに重ならず、
  全て親の keep の部分集合である（検証の節で確認）。

## 検証結果（すべて実測）

アプリ自身のコード（`docs/dicom.js`, `docs/slice-spacing.js`, `docs/project-file.js` を Node で実行）による検証:

- **CT シリーズ**: 242 スライスを 1 シリーズとして認識。Modality CT、124 列 × 76 行、
  spacing 0.28 × 0.28 × 0.28 mm、compact（Int16）true、sourceBacked false、展開 4,561,216 bytes。
  画素実測の値域は元データどおり −1000〜3716 HU。
- **ラベルシリーズ**: 同一形状・同一 spacing、値域 0〜13（存在する値は 0, 1, 3〜13。2 はボクセルなし）。
- **spacingCheck**: 両シリーズとも `warn: false`、重複 0・欠落 0・ばらつき 5.1e-12 %、タグ間隔との不一致なし。
- **プロジェクト（最終・アプリ保存版）**: アプリで正常に開け、zip 内エントリは
  project.json + `edits/bone-keep.bin` / `edits/lung-keep.bin` / `edits/contrast-keep.bin` +
  `treesegments/seg-1.bin` 〜 `seg-11.bin`（子セグメント 11 件）。
  `compareFingerprints` は ok、`resolveProjectMatch` は **apply**。解析領域は 11 件含まれる。
- **子セグメント**: アプリに読み戻して検証。各子のボクセル数はラベル実測と全て一致
  （心臓 10,646 / 膀胱 1,309 / 腎臓 16,913 / 胃 3,540 / 筋肉 3,960 / 脾臓 7,947 / 肝臓 73,719 /
  腸 77,988 / 腫瘍 7,525 / 肺 27,055 / 気管 271）。子同士の重なり 0、全て親 keep の部分集合で、
  親の表示（keep − 子の合体）は contrast・lung とも **0**、bone は子がなく 38,445 のまま。
- **セグメントマスク**: `decodeRuns` で 3 セグメントの keep マスクを復号し、ラベルボリューム
  （`dicom_labels` 全 242 枚と画素単位で一致することを変換時に確認済みの作業ボリューム）と集合として比較:
  **骨 38,445 / 肺 27,326 / 造影 203,547 ボクセル、全て集合の不一致 0**、合計 269,318 は
  ラベル付きボクセル総数と一致。
- **実画面**: プロジェクト適用時にフッターへ「プロジェクトを適用しました」と表示され、
  セグメントパネルには造影・骨・肺の 3 カード（軟部・脂肪は非表示）と、造影領域・肺の下位に
  子セグメントのツリーが表示された。3D（GPU ボリューム）では臓器・腫瘍が子ごとに色分けされて
  表示されることをスクリーンショットで目視確認した（撮影は別途実施、本一式には含まない）。
