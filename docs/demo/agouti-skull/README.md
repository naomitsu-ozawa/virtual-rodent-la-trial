# アグーチ頭蓋 microCT データセット（Virtual Rodent Lab 体験版用）

Virtual Rodent Lab — 体験版（`naomitsu-ozawa/virtual-rodent-la-trial`、以下 VRL）で
そのまま読み込める形に変換した、アグーチ（*Dasyprocta agouti*）頭蓋 microCT の
DICOM 一式とプロジェクトファイルです。
リポジトリ自体には一切手を入れていません（読み取りのみで仕様を確認し、成果物はこのフォルダに置いています）。

**学習形式について**: 出典セグメンテーションの各クラスは、骨セグメントの下位の
「子セグメント」として**名称なし・色分けのみ**で登録してあります。
どの色がどの骨かは本書にも `sample.json` にも書いていません
（ラベル値とボクセル数の対応だけを記録します）。各骨の同定は、
アプリの中で構造を見分けて学習者自身が名前を付ける課題です。

## 中身

| パス | 内容 |
|---|---|
| `dicom_ct/` | 頭蓋 CT の DICOM シリーズ（469 ファイル、`AgoutiSkullCT_0001.dcm` 〜 `AgoutiSkullCT_0469.dcm`、約 149 MB） |
| `dicom_labels/` | 頭蓋ラベルの DICOM シリーズ（469 ファイル、`AgoutiSkullLabels_0001.dcm` 〜、約 76 MB）。CT と同一グリッド、値 0〜15 |
| `agouti_skull.vrlab` | VRL プロジェクトファイル（CT シリーズに紐付き、骨セグメントの keep マスク＋名称なし子セグメント 14 件入り） |
| `sample.json` | VRL 練習データ形式のメタ情報（出典・ライセンス・変更点・利用条件） |
| `screenshot_children_3d.png` | アプリ実画面の 3D 表示（GPU ボリューム、子セグメント色分け） |

## VRL での使い方

1. VRL で `dicom_ct` フォルダの DICOM を読み込む（CT シリーズが自動選択される）。
2. プロジェクトファイル `agouti_skull.vrlab` を読み込むと、表示ウィンドウ（中心 19802 / 幅 25587）と
   セグメントが適用される。骨セグメントの下位に子セグメント 14 件が色分けで登録されており、
   名前・色・表示をクラスごとに切り替えられる。親（骨）自身の表示は子の差し引きで 0 になる。
3. `dicom_labels` は別シリーズとして読み込める（値 0〜15 がラベルクラス）。
   CT と ImagePositionPatient グリッドが完全一致するので、外部ツールでもボクセル単位で対応づけられる。

## 間隔（ボクセルサイズ）について — ファイル内メタデータからの導出

論文（bioRxiv 2024, DOI: 10.1101/2024.11.22.624847）にもデータセット README にも、
本個体のボクセル間隔の記載は無い。一方、TIFF の ImageDescription には Amira 形式の
BoundingBox（`0.0146503 59.7747 0.0237007 68.9037 -0.0189934 122.261`）が記録されており、
各軸の広がりを（ボクセル数 − 1）で割ると 3 軸とも **0.1200 mm** できれいに割り切れる。
本変換ではこの値を元グリッドの間隔（0.12 mm 等方）として DICOM に記録した。
これはファイル自身のメタデータからの導出であり、推測で埋めた値ではない。

## 元データの実測結果（変換前の検査）

- スキャン: uint16、グリッド 1020 スライス × 575 行 × 499 列。値域は **0〜65535**（uint16 全域）。
  HU 較正は無く、スキャナの処理値である（**HU ではない**）。
  DICOM は符号付き 16-bit のため、格納値は元値を一律 **1/2 に線形スケール**した 0〜32767 とした
  （相対的な濃淡関係は保存される。この変換は各ファイルの DerivationDescription にも明記した）。
- セグメンテーション: uint32、同一グリッド。クラス値は 0（背景）〜15。
  本個体では値 **12 のクラスが元データに存在しない**（出現するクラスは 14 種類）。
  クラスごとの名称対応は学習形式のため本書には記載しない。

## 変換内容（何をどう変えたか）

1. **クロップ**（元ボクセル座標）: ラベル全体の bbox に 8 ボクセルの余白を追加し、
   z 39〜975 / y 60〜496 / x 61〜435 を切り出した（937 × 437 × 375）。
   切り出し後も全クラスが漏れなく含まれる（ボクセル数が元と一致）。
2. **間引き**: VRL の上限（各辺 512 ボクセル）に収めるため、スライス方向のみ
   ステップ 2 で間引いた（面内はステップ 1）。出力グリッドは **469 スライス × 437 行 × 375 列**、
   実効間隔は z 0.24 mm × y 0.12 mm × x 0.12 mm。
   - CT: 2 スライスのブロック平均。
   - ラベル: ブロック内の OR プーリング（最も希少なクラスを優先）。薄い骨でも
     クラスが消えない方式で、**消滅したクラスは 0 件**（下表は間引き後の実測）。
3. **タグの付け替え**（前例の変換と同一規約）:
   - 新 Study / Series Instance UID（2.25.* 形式で生成）。元データに DICOM UID も撮像日も
     無いため、日付タグは変換日（2026-11-11）になっている。
   - CT シリーズ: CT Image Storage、Modality `CT`、符号付き 16-bit、非圧縮 Explicit VR Little Endian。
     Window Center 19802 / Width 25587（非ゼロボクセルの p2〜p98 から設定した一般表示用ウィンドウ）。
   - ラベルシリーズ: Secondary Capture / Modality `SC`、8-bit、値は元のクラス値のまま。
   - 各ファイルに DerivationDescription (0008,2111) として変換内容を英語で記録。

## プロジェクトファイルの中身

- 形式: ZIP + `project.json`（`format: "virtual-rodent-lab-project"`, `version: 1`、拡張子 `.vrlab`）。
- 最終ファイルは VRL アプリ自身の保存機能で
  書き出したもの（savedAt `2026-11-11T00:37:03Z`）。外部スクリプトで直接組み立てたファイルではない。
- セグメント構成:
  - **bone**: 有効。範囲は格納値全域 0〜32767 に開け、keep マスク = ラベル値 ≥ 1 の全ボクセル
    （3,501,137）。最終表示 = 範囲 ∩ keep = ラベル集合そのもの。
  - **soft / fat / lung / contrast**: 無効（頭蓋骨のみのデータで、プリセットの意味に合う実体が無いため）。
  - **子セグメント 14 件**（treeSegments）: 上表の各クラスを bone の下位に
    **名称なし**で登録。色はアプリの子セグメント用パレット（CHILD_SEG_COLORS）を
    ラベル値の昇順に割り当てた。子のボクセルは親の表示から差し引かれるため、
    親（骨）自身の表示は **0** になり、表示は全て子が担う。
- 解析領域・ピンは入れていない（学習者が自分で同定・ラベル付けする形式）。

## 検証結果（すべて実測）

- **プロジェクト読み戻し**: アプリに新規セッションで読み込み、
  適用判定は **apply**（指紋一致）。保存時と適用時で子セグメント 14 件が
  完全に一致した。
- **子セグメント**: 各子のボクセル数が間引き後ラベルの実測と **全件一致**（上表）。
  子同士は互いに重ならず（disjoint）、全て親 keep の部分集合で、
  親の表示（keep − 子の合計 3,501,137）は **0**。
- **DICOM**: CT 469 枚・ラベル 469 枚とも変換作業ボリュームと画素一致を確認済み。
- **実画面**: アプリで GPU ボリューム表示の 3D スクリーンショットを取得し
  目視確認した（`screenshot_children_3d.png`、表面／メッシュ生成は使わない方式）。
  子セグメント 14 件が色分けで描かれ、頭蓋全体が画面に収まることを確認した。
