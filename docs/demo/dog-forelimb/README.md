# イヌ前肢 CT データセット（Virtual Rodent Lab 体験版用）

イヌ（ダックスフント）の前肢の臨床CTと、その参照セグメンテーション（骨ラベル4クラス）を、Virtual Rodent Lab で読み込める DICOM ＋ プロジェクトファイルのセットに変換したもの。

**教材形式について**：このデータセットでは、骨ラベル4クラス分を**名称なし**の子セグメントとして登録してあります（色分けのみ）。骨の名前は付けてありません。学習者がアプリの中で構造を見分けて、自分で名前を付けていく使い方を想定しています。

## 中身

- `dicom_ct/` — CT 本体の DICOM 151 枚（`DogForelimbCT_0001.dcm` 〜）
- `dicom_labels/` — ラベル（参照セグメンテーション）の DICOM 151 枚（`DogForelimbLabels_0001.dcm` 〜）
- `dog_forelimb_228420.vrlab` — プロジェクトファイル（セグメント＋子セグメントの登録）
- `sample.json` — 練習データとしての登録情報
- `screenshot_children_3d.png` — アプリでの 3D 表示（GPUボリューム、子セグメント色分け）

## VRL での使い方

DICOM フォルダと `.vrlab` をアプリで読み込むと、プロジェクトが適用され、骨セグメントの下に色分けされた4つの子セグメント（名称なし）が表示されます。子セグメントは1つずつ表示/非表示・名前の編集ができます。

## 選んだ個体と根拠

採用：**228420_Dachshund**（ダックスフント、train/test 分割では test 側）

- 参照セグメンテーションに骨ラベル4クラスがすべて含まれている（15個体共通）
- グリッド 151×226×116 で全軸 512 以下 → ダウンサンプル・間引きなしで変換できる
- 間隔がほぼ等方（0.808 × 0.808 × 0.800 mm）で、15個体の中で最も小さいボリュームのためアプリでの表示も軽い

## 元データの実測結果（変換前の検査）

- 形式：8-bit TIFF スタック（LZW圧縮）。スキャンと参照セグメンテーションは同一グリッド（151ページ×226行×116列）
- CT の値域：0–255 の **8-bit 処理値であり、HU ではない**（臨床CTを8-bit化したもの）
- ラベル：0 = 背景、1–4 = 骨4クラス。実測ボクセル数（全ボリューム）：クラス1 = 12,311／クラス2 = 5,298／クラス3 = 13,531／クラス4 = 5,214、合計 36,354
- CT には軟部組織や、ラベル対象外の骨（前足の骨など）も写っている。参照セグメンテーションの対象は前肢の4骨のみ

## 間隔（ボクセルサイズ）について

TIFF の ImageDescription に記録された物理バウンディングボックス（"BoundingBox 0 92.9201 0 181.8 0 120"）から、各軸の間隔 = 物理エクステント ÷ (ボクセル数 − 1) で復元した：

- 面内：92.9201 ÷ 115 = 181.8 ÷ 225 = **0.808 mm**
- スライス方向：120 ÷ 150 = **0.800 mm**

同じ計算を15個体すべてに行うと全個体で割り切れる値（面内は犬種ごとに 0.463–1.25 mm、スライス方向は1個体を除き 0.800 mm）になり、この復元の正しさを確認できた。元ファイルに DICOM の UIDs や撮影日時は含まれないため、本変換で新規に採番し、日時タグには変換日を入れてある。

## 変換内容（何をどう変えたか）

- TIFF スタックを DICOM に変換（CT は CT Image Storage・符号付き16-bit に格納、ラベルは Secondary Capture・8-bit）。格納値は元の8-bit値をそのまま保持（再スケーリングなし）
- クロップ：(CT > 0 またはラベル > 0) のバウンディングボックス＋3ボクセル余白で計算した結果が全ボリュームと一致したため、実質クロップなし（元データ自体が前肢にクロップ済み）
- リサンプリングなし。全軸 ≤ 512 を満たす

## プロジェクトファイルの中身

アプリ自身の保存経路で作成。

### セグメント（ラベル由来の keep マスク）

- 骨セグメントのみ有効。keep マスク = ラベル4クラスの合体（36,354 ボクセル）、値範囲は全域（0–255）に開け、マスクで切り取る形
- 軟部・脂肪・肺・造影領域は無効（出典にラベルがないため）
- 解析領域は 0 件。重なり設定は「重複なし（上のカードが優先）」

### 子セグメント（treeSegments）

骨セグメントの下位に、ラベル4クラスを個別の子セグメントとして登録。**名前は付けていない**（アプリ上は「セグメント 1〜4」と表示される）。子のボクセルは親から差し引かれるため、親セグメント単独の表示は 0 になる。

| 子セグメント | 色 | ボクセル数 |
|---|---|---|
| セグメント 1 | #00d8ff | 12,311 |
| セグメント 2 | #ff9f1c | 5,298 |
| セグメント 3 | #7ae582 | 13,531 |
| セグメント 4 | #ff4d8d | 5,214 |

## 検証結果（すべて実測）

- アプリへの読み戻し：指紋照合 OK、適用判定 = apply
- 子セグメント4件のボクセル数 = ラベル実測と全件一致（上表）
- 親の算術：骨 keep 36,354 − 子の合計 36,354 = 親の表示 0。子同士の重なり 0、全ての子が親 keep の部分集合
- 3D スクリーンショットを目視確認：4骨が別々の色で表示され、解剖学的な位置関係（扁平な骨が近位、長骨がそれに続く）も元ラベルと一致。空気や背景への色乗りなし
