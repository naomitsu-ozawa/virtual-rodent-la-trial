# イエネコ頭蓋 microCT データセット（Virtual Rodent Lab 体験版用）

Virtual Rodent Lab — 体験版（`naomitsu-ozawa/virtual-rodent-la-trial`、以下 VRL）で
そのまま読み込める形に変換した、イエネコ（*Felis catus*）頭蓋 microCT の
DICOM 一式とプロジェクトファイルです。
リポジトリ自体には一切手を入れていません（読み取りのみで仕様を確認し、成果物はこのフォルダに置いています）。

**2026-11-13 改訂**: 出典セグメンテーションが頭蓋の骨をカバーしきれていなかったため、
当方で補完を行いました（詳細は「当方による補完（2026-11-13）」の節）。
子セグメントは全 17 件で、出典の 15 クラス（名称付き）に、
当方が分離した「歯」と「骨（未分類）」が加わっています。
補完分・歯・未分類は出典のセグメンテーションではなく当方の推定です。

## 中身

| パス | 内容 |
|---|---|
| `dicom_ct/` | 頭蓋 CT の DICOM シリーズ（348 ファイル、`CatSkullCT_0001.dcm` 〜 `CatSkullCT_0348.dcm`、約 74 MB）。初版から変更なし |
| `dicom_labels/` | 頭蓋ラベルの DICOM シリーズ（348 ファイル、`CatSkullLabels_0001.dcm` 〜）。CT と同一グリッド、値 0〜17（16=歯、17=骨（未分類）は 2026-11-13 の補完で追加） |
| `cat_skull.vrlab` | VRL プロジェクトファイル（CT シリーズに紐付き、骨セグメントの keep マスク＋子セグメント 17 件入り） |
| `sample.json` | VRL 練習データ形式のメタ情報（出典・ライセンス・変更点・利用条件） |
| `render_completed_3d.png` | 変換後データからのオフライン 3D レンダリング（腹側・側面）。歯（白）と骨（未分類）（灰）が見分けられる。アプリ実画面のスクリーンショットではない |
| `screenshot_completed_3d.png` / `screenshot_completed_3d_alt.png` | アプリ実画面の 3D 表示（GPU ボリューム、子セグメント色分け） |

## VRL での使い方

1. VRL で `dicom_ct` フォルダの DICOM を読み込む（CT シリーズが自動選択される）。
2. プロジェクトファイル `cat_skull.vrlab` を読み込むと、表示ウィンドウ（中心 16616 / 幅 30969）と
   セグメントが適用される。骨セグメントの下位に子セグメント 17 件が色分けで登録されており、
   名前・色・表示をクラスごとに切り替えられる。親（骨）自身の表示は子の差し引きで 0 になる。
3. `dicom_labels` は別シリーズとして読み込める（値 0〜17 がラベルクラス）。
   CT と ImagePositionPatient グリッドが完全一致するので、外部ツールでもボクセル単位で対応づけられる。

## 当方による補完（2026-11-13）

出典（SPROUT）の 15 クラスセグメンテーションは、頭蓋の骨の一部をカバーしていなかった。
実測では、骨らしいボクセル（格納値 ≥ 6000）のうち約 31.6 万ボクセルが出典ラベルの外にあり、
内訳は主に (a) 出典のクラス体系に含まれない構造（歯、および頭蓋底〜鼻腔・口蓋の正中複合体＝
蝶形骨・鋤骨・口蓋骨・翼状骨・篩骨など）と、(b) 出典クラスの表面に接する薄い層だった。
そこで次の改変を行った（CT 本体は変更していない）。

- **補完マスク**: 格納値 ≥ 6000 かつ出典ラベル外のボクセル（微小成分を除く 316,388 ボクセル）を増分とした。
  形態学的な穴埋め・クロージングは空気を大量に含むため使っていない。
- **歯の分離**: 増分の連結成分のうち、位置・形状・高い格納値（平均 25,000〜26,600）から
  歯と同定された 8 成分（上顎犬歯の左右対 29,693 / 29,380、上顎頬歯の左右対 28,386 / 28,346、
  切歯の対 3,968 / 3,966、上顎小臼歯（犬歯の直後）の対 1,035 / 992、合計 125,766 ボクセル）を、
  骨クラスのどれにも配属せず、
  独立した子セグメント「歯」（ラベル値 16、色 #ffffff）として登録した。
  なお小臼歯の対は初回の同定から漏れており（上顎骨への表面層配属と未分類に分かれていた）、
  2026-11-13 の監査（増分の全連結成分を対象に、格納値・位置・歯列の並びで再判定）で検出し、
  丸ごと歯セグメントへ移した。
- **表面層の配属**: 歯以外の増分のうち、既存の出典クラスから 3 ボクセル以内の層
  （35,228 ボクセル）だけを、最も近い出典クラスへ配属した。
  それより内側については、どの骨に属すかをデータから決められないため配属していない
  （縫合線を推定で作らないための判断）。
- **骨（未分類）**: 残り 155,394 ボクセル（頭蓋底〜鼻腔・口蓋の正中複合体が主体）を、
  子セグメント「骨（未分類）」（ラベル値 17、色 #a6a6a6）として登録した。
  表示を個別に切り替えられるので、未分類の範囲だけを分離して確認できる。

**注意**: 補完分（配属した表面層・歯・骨（未分類））は出典 SPROUT のセグメンテーションではなく、
当方が閾値と形状から推定したものである。出典の 15 クラスそのものには手を入れていない
（各クラスの増分は上記の表面層の配属分のみ）。

## 間隔（ボクセルサイズ）について — ファイル内メタデータからの導出

論文（bioRxiv 2024, DOI: 10.1101/2024.11.22.624847）にもデータセット README にも、
本個体のボクセル間隔の記載は無い。一方、TIFF の ImageDescription には Amira 形式の
BoundingBox（`-0.000148773 67.3199 0.00143814 51.8414 0.0103035 93.7003`）が記録されており、
各軸の広がりを（ボクセル数 − 1）で割ると 3 軸とも **0.0900 mm** できれいに割り切れる。
本変換ではこの値を元グリッドの間隔（0.09 mm 等方）として DICOM に記録した。
これはファイル自身のメタデータからの導出であり、推測で埋めた値ではない。

## 元データの実測結果（変換前の検査）

- スキャン: uint16、グリッド 1042 スライス × 577 行 × 749 列。値域は **0〜65535**（uint16 全域）。
  HU 較正は無く、スキャナの処理値である（**HU ではない**）。
  DICOM は符号付き 16-bit のため、格納値は元値を一律 **1/2 に線形スケール**した 0〜32767 とした
  （相対的な濃淡関係は保存される。この変換は各ファイルの DerivationDescription にも明記した）。
- セグメンテーション: uint32、同一グリッド。クラス値は 0（背景）〜15 で、
  **全 15 クラスが存在する**。
- 頭蓋がスキャンの全グリッドに及ぶため、切り出し（クロップ）は行っていない。

## 変換内容（何をどう変えたか）

1. **クロップ**: なし（上記のとおり）。
2. **間引き**: VRL の上限（各辺 512 ボクセル）に収めるため、ブロック平均で
   z ステップ 3・y ステップ 2・x ステップ 2 で間引いた。
   出力グリッドは **348 スライス × 289 行 × 375 列**、
   実効間隔は z 0.27 mm × y 0.18 mm × x 0.18 mm。
   - CT: ブロック内の平均。
   - ラベル: ブロック内の OR プーリング（最も希少なクラスを優先）。薄い骨でも
     クラスが消えない方式で、**消滅したクラスは 0 件**（下表は間引き後の実測）。
3. **タグの付け替え**（前例の変換と同一規約）:
   - 新 Study / Series Instance UID（2.25.* 形式で生成）。元データに DICOM UID も撮像日も
     無いため、日付タグは変換日（2026-11-11）になっている。
   - CT シリーズ: CT Image Storage、Modality `CT`、符号付き 16-bit、非圧縮 Explicit VR Little Endian。
     Window Center 16616 / Width 30969（非ゼロボクセルの p2〜p98 から設定した一般表示用ウィンドウ）。
   - ラベルシリーズ: Secondary Capture / Modality `SC`、8-bit、値は元のクラス値のまま。
   - 各ファイルに DerivationDescription (0008,2111) として変換内容を英語で記録
     （ラベルシリーズには 2026-11-13 の補完についての注記も追記した）。
4. **骨マスクの補完（2026-11-13）**: 「当方による補完」の節のとおり。
   ラベル値を 0〜17 に拡張し、骨セグメントの keep マスクを補完後の全ラベル（値 ≥ 1）に合わせて再作成した。
   DICOM CT 本体は変更していない。

## プロジェクトファイルの中身

- 形式: ZIP + `project.json`（`format: "virtual-rodent-lab-project"`, `version: 1`、拡張子 `.vrlab`）。
- 最終ファイルは build 708 の VRL アプリ自身の保存経路（`gatherProject` → `packProject`）で
  書き出したもの。外部スクリプトで直接組み立てたファイルではない。
- セグメント構成:
  - **bone**: 有効。範囲は格納値全域 0〜32767 に開け、keep マスク = ラベル値 ≥ 1 の全ボクセル
    （2,574,995）。最終表示 = 範囲 ∩ keep = ラベル集合そのもの。
  - **soft / fat / lung / contrast**: 無効（頭蓋骨のみのデータで、プリセットの意味に合う実体が無いため）。
  - **子セグメント 17 件**（build 708 の treeSegments）: 上表の各クラスを bone の下位に登録。
    子のボクセルは親の表示から差し引かれるため、
    親（骨）自身の表示は **0** になり、表示は全て子が担う。
- 解析領域・ピンは入れていない。
